# 최종 인계 패키지 — D055

사용자는 **전체 1차 구현과 테스트 완료 후** 다른 PC에서도 에이전트와 고도화를 계속할 수 있도록 전체 인계 패키지를 만들고 그 패키지 자체를 GitHub로 관리하도록 지시했다. 이번 저장·재열기 preview를 이 완료 시점으로 오해하지 않는다.

최종 패키지에는 다음이 필요하다.

1. TPS 실제 소스, 빌드 래퍼·잠금 파일·설정, 단위/통합/브라우저 테스트와 검증 결과.
2. 기록 정본의 설계·분석·결정·명세·작업 규칙·하네스·스킬·핸드오프·향후 계획, 최종 설계 PDF와 사용자 매뉴얼 및 편집 원본.
3. 기록이 참조하는 RPS/LPS/복원된 `_ref`/하네스/REA/CMOS/매뉴얼 등 참조 자료·소스의 필요한 스냅샷. 절대 경로만 남기지 않고 실제 파일을 패키지 내부에 수집한다. 원본 위치·버전·해시와 포함 여부의 manifest를 만든다.
4. DB 생성·스키마·테이블·변경·데이터 이관 스크립트, 실제 적용 내역과 검증, 새 개발 DB를 재현하는 순서. 기존 데이터 덮어쓰기와 자동 운영 이관을 금지한다.
5. 새 PC의 JDK/Node/Maven·Gradle/REA MCP/선택 IDE 설치·연결 안내, 버전·의존성 명세, 재현 시험. 특정 PC의 전역 Eclipse·경로·환경 설정에 의존하지 않는다.
6. 새 에이전트가 처음 읽을 단일 진입 안내, 우선순위 규칙, 확정/미확정 결정, 완료/미검증 범위, 다음 작업과 재개 절차.

패키지 내 상대 경로 및 원래 경로→패키지 경로 매핑을 사용한다. 암호·토큰·개인 키는 넣지 않고 새 환경에서 주입한다. 참조 자료/실제 데이터의 포함 범위와 저장소 공개 범위·대용량 Git 관리 방식은 최종 패키지를 구체적으로 준비할 때 검증하며 자료를 조용히 누락하지 않는다. 외부 저장소에 링크만 남기는 것으로 전체 수집 완료를 대신하지 않는다.

최종 수용 조건: 깨끗한 다른 PC에 패키지와 저장소만 내려받고, 별도 비밀값을 주입한 뒤 DB 준비·빌드·실행·시험을 재현한다. 새 에이전트가 규칙과 설계·참조 소스를 찾아 다음 작업을 이어가는지도 검증한다. 현재는 이 조건을 기록했으며 최종 인계 패키지를 생성/업로드하지 않았다.
